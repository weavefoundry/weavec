Each release publishes a self-contained toolchain for **macOS on Apple silicon** (macOS 14 or later) and for **Linux on x86-64 and AArch64** (glibc 2.35 or later: Ubuntu 22.04, Debian 12, Fedora 36 and later). A toolchain is one directory: `weavec-cc`, WeaveC's runtime, and Clang's headers and builtins. It needs no LLVM installation, only the platform's linker, C library headers and start-up files, and it may be moved anywhere. The runtime that `weavec-cc` links into the programs it builds supports 64-bit macOS and Linux targets; for any other target `weavec-cc` builds without it.

## 1. Install the platform's C toolchain

<Tabs>
<TabItem label="macOS">

```sh
xcode-select --install
```

The Command Line Tools provide the linker, the SDK's headers and the system assembler.

</TabItem>
<TabItem label="Ubuntu / Debian">

```sh
sudo apt-get install -y build-essential
```

`build-essential` provides the linker (`ld`), the assembler, and the C library's headers and start-up files.

</TabItem>
</Tabs>

## 2. Install WeaveC

<Tabs>
<TabItem label="Release archive">

Download `weavec-X.Y.Z-<os>-<arch>.tar.xz` for your platform (`darwin-arm64`, `linux-x86_64` or `linux-aarch64`) and `SHA256SUMS` from [GitHub Releases](https://github.com/weavefoundry/weavec/releases) into one directory, check the archive, unpack it and put its `bin` on `PATH`:

```sh
shasum -a 256 --ignore-missing -c SHA256SUMS   # sha256sum --ignore-missing -c on Linux
tar -xJf weavec-X.Y.Z-linux-x86_64.tar.xz -C "$HOME/.local/opt"
export PATH="$HOME/.local/opt/weavec-X.Y.Z-linux-x86_64/bin:$PATH"
```

On macOS, remove the quarantine attribute a browser sets on the download before the first run; the toolchain is not yet notarized:

```sh
xattr -dr com.apple.quarantine weavec-X.Y.Z-darwin-arm64
```

Add the `PATH` export to your shell configuration to keep it in new terminals.

</TabItem>
<TabItem label="Homebrew">

```sh
brew install weavefoundry/tap/weavec
```

</TabItem>
<TabItem label="Container">

```sh
docker run --rm -v "$PWD:/src" ghcr.io/weavefoundry/weavec:X.Y.Z weavec-cc -O2 main.c -o main
```

The image is Ubuntu 24.04 with the toolchain on `PATH`, `CC=weavec-cc` and `build-essential`, for linux/amd64 and linux/arm64.

</TabItem>
</Tabs>

The tree holds `bin/weavec-cc`, WeaveC's files in `lib/weavec/` (`weavec.h` under `include/`, the runtime's library `libweavec_rt.dylib` or `libweavec_rt.so.<abi>`, and on Linux `libweavec_rt.a` for static programs), and Clang's headers and builtins in `lib/clang/<major>/`; on macOS `lib/weavec/llvm/` holds the LLVM libraries `weavec-cc` loads. `weavec-cc` finds all of them from its own location, so move the tree as a whole.

A program `weavec-cc` builds loads `libweavec_rt` from the toolchain at run time. To run it elsewhere, ship the library with it (see [build integration](/guides/build-integration/)).

## 3. Verify the installation

```sh
weavec-cc --version
```

It prints Clang's version, then `weavec-cc version X.Y.Z`, the LLVM version it was built with, and the runtime's interface version and platform. To check that the runtime links, compile and run an empty program:

```sh
printf 'int main(void) { return 0; }\n' > empty.c
weavec-cc empty.c -o empty && ./empty && echo ok
```

It should print `ok` with no note about building without the WeaveC runtime. If something cannot be found, check [troubleshooting](/reference/troubleshooting/).

## Building from source

Building needs **CMake 3.25 or newer**, Ninja, a C++20 compiler, and an LLVM/Clang development installation (LLVM **23.x** recommended, **20 and newer** supported); the tests also need `lit` and LLVM's `FileCheck`. On macOS, `brew install cmake llvm ninja lit` and `export WEAVEC_LLVM_PREFIX="$(brew --prefix llvm)"`; on Ubuntu, the [official LLVM packages](https://apt.llvm.org/) (`sudo bash llvm.sh 23 all`, then `WEAVEC_LLVM_PREFIX=/usr/lib/llvm-23 CC=clang-23 CXX=clang++-23`). Then, from a source archive or a clone:

```sh
cmake --preset release -DWEAVEC_VERSION_SUFFIX=""
cmake --build --preset release
ctest --preset release
cmake --install build/release --prefix "$HOME/.local/opt/weavec"
```

The `release` preset builds a self-contained toolchain (`WEAVEC_SELF_CONTAINED`: LLVM linked statically on Linux, its libraries copied into the tree on macOS); `cpack` in `build/release` packs it as a release archive. The [developer guide](/contributing/development/) covers debug builds, other LLVM installations and the build options.
